# GiftMind 移动端列表与选择链路体验审查

审查日期：2026-08-12
视口：390 × 844
范围：首页入口 → 我的方案 → 四类推荐榜单 → 选择礼物 → 信件与送出方式 → 分享页

## 结论

主链路已经可用，入口与分享编辑器的视觉完成度较高。本轮最影响选择效率的三个问题是：推荐卡信息同时全部展开、榜单缺少名次与分数的快速判断、历史列表沿用旧的“2 件礼物”口径。以上问题均已在本轮修复。

## 同步修复

- 目录文案中的“他 / 她”会按照收礼人身份自动校正；未知性别统一使用 `TA`，用户自己填写的回忆原文不会被改写。
- 历史方案只存在本机、后端查不到回信时，页面不再产生未处理错误；回信是增强项，不阻断方案浏览。
- 搜索框使用项目现有图标库，不再用 CSS 拼图标。

## 下一轮优先级

1. 让用户对单个推荐做“喜欢 / 不喜欢”的轻反馈，并把理由带回下一次重排。
2. 在四榜之间标出重复候选，例如“同时也是最省心第 1 名”，帮助理解而不是把重复误认为数据不足。
3. 选择礼物后增加简短的对比回顾：为什么最终选择它，以及它牺牲了什么。
4. 分享链接生成后增加微信发送文案和封面预览，减少用户从生成到真正发出的断点。
